# v1.7.1 작업 계획

- 상태: **설계 초안 — 구현·배포 전**
- 대상: **전체 게임 v1.7.1**
- 포함할 시나리오 버전: **v0.3.2** · [시나리오·멀티 통합 범위](SCENARIO_0_3_2_PLAN.md)
- 기준 코드: `2b11359` / `v1.7.0-obt.3` · 현재 시나리오 버전 `0.3.1`
- 범위: 세계지도·시나리오 연동, 시나리오 오류 검사 강화, 앱 전반 성능 최적화, Steam 시나리오 멀티플레이, 지도상의 경제권, 시나리오 메이커 확장·플레이 중 편집 잠금

이 항목들은 모두 **v1.7.1의 목표**로 묶습니다. 시나리오·메이커·멀티 관련 상세는 **시나리오 0.3.2**에 모아 기록하며 같은 업데이트에 포함합니다. 지도상의 경제권 자체와 앱 전반 최적화는 전체 게임 범위이고, 시나리오에서의 연동·제작·실행·동기화는 0.3.2에도 포함합니다. 현재 동작하는 기능이나 완료한 변경 사항으로 취급하지 않으며, 이 계획을 적었다는 이유로 현재 앱의 버전·빌드 날짜를 출시 값으로 바꾸지 않습니다.

## 2. 세계지도·시나리오 연동

[상세 설계](SCENARIO_WORLD_INTEGRATION.md)의 국가 연결·소유 조건·영토 효과·실패 처리·저장 복원 계약을 v1.7.1에 포함합니다. 첫 검증 예제는 **국경 협정**입니다.

지도에서 영토가 바뀌면 날짜를 더 넘기지 않고 관련 조건을 다시 검사합니다. 정보 전달용 시나리오 기사는 선택지·경제 효과를 갖지 않으며, 선택과 효과는 이벤트가 담당합니다. 선거용 지역구·의석·결과는 유지합니다.

경제권은 영토 소유와 다른 지도 레이어입니다. 영토 양도만으로 경제권 경계가 바뀌지 않도록 두 상태를 분리합니다.

## 3. 시나리오 오류 검사 강화

### 검사 범위

| 분류 | 찾아낼 문제 | 처리 기준 |
|---|---|---|
| 구조 | 잘못된 배열/객체, ID 중복, 숫자 범위, 실제로 없는 날짜 | 오류, 해당 필드 경로 표시 |
| 조건·효과 | 알려진 연산자의 잘못된 인수, 중첩 `all`·`any`·`not`, 범위·확률·변수 참조 오류 | 연산자별로 재귀 검사 |
| 참조 | 없는 방향성·결정·기술·부대/장비·시설·자원·무역 계약·이벤트·기사·격변·국가·구역·경제권, 실행 시 같은 이름으로 충돌하는 이벤트 ID | 실제 실행 네임스페이스를 기준으로 검사 |
| 방향성 | 순환, 없는 선행 항목, 배타 경로를 동시에 요구하는 필수 선행 | 확실한 구조적 불가능은 오류 |
| 이벤트 | 조건 없는 즉시 반복, 연쇄 이벤트 순환, 보이지 않거나 선택할 수 있는 선택지가 없는 상태 | 증명 가능한 문제는 오류, 상태에 따라 달라지면 경고 |
| 시간·시작 상태 | 턴제/실시간 설정, 모든 시작 세이브의 지도·국가 연결, 필요한 초기 변수/데이터 누락 | 시작 나라별 결과 표시 |
| 경제권 | 없는 구역, 중복 배정, 잘못된 값·단위, 삭제된 경제권 참조 | 경제권 레이어와 작성 데이터 양쪽 검사 |
| 운영 시스템·권한 | 연구 선행·비용/자원 중복 지출·무역 정산·보급/생산 규칙 불일치, 잠금과 허용 행동의 모순 | 모듈별 규칙·직접 수정/정상 행동·국가별 권한 함께 검사 |
| 멀티플레이 | 참가 가능 국가 부족/중복, 권한 없는 전역 효과, 다른 국가 진행에 필요한 상태 누락 | 싱글 검사와 멀티 호환 검사 구분 |

현재 `campaign-tools.js`의 조건/효과 검사는 주로 바깥 자료형을 검사하므로 내부 연산자의 의미 검사를 추가해야 합니다. 현재처럼 기본 구조가 잘못된 경우 먼저 오류를 내고, 안전하게 읽을 수 있는 다른 항목의 검사도 계속합니다. 잘못된 입력 하나 때문에 검사기 자체가 멈추지 않아야 합니다.

정적 검사로 모든 플레이 경로의 성공을 보장하지 않습니다. 플래그·확률·변수·플레이어 선택이 얽힌 도달 가능성은 **확인 필요**로 표시하고 시험 플레이에서 추적합니다. 알려지지 않은 확장 키는 경고하고 보존하며, 오타와 확장 기능을 구분할 단서를 제공합니다. 알려진 연산자의 잘못된 인수는 오류입니다.

### 제작자 경험

- 검사 결과는 **오류 / 경고 / 확인 필요**로 나누고 개수·항목명·이유·수정 위치를 보여줍니다.
- 예: `events.2.options.0.effects.0.transfer_regions.regions.1` → “국경 협상 › 수락 › 영토 변경: 없는 구역 `riverbank_old`”.
- 결과를 누르면 가이드의 해당 항목 또는 프로 JSON 위치로 이동합니다. 화면을 바꿔도 미적용 JSON·입력·선택을 잃지 않습니다.
- 입력 중 검사는 지연 실행하고, 수동 **검사**는 전체를 검사합니다. 오래된 비동기 결과로 최신 입력의 오류 표시를 덮지 않습니다.
- 원본 보관을 위한 저장·내보내기는 오류가 있어도 가능하게 합니다. 시험 플레이와 멀티 시작은 실행에 필요한 오류가 해결되어야 하며, 경고만으로는 막지 않습니다.
- 시험 플레이에서 마지막 조건 평가·이벤트 연쇄·효과 실패를 추적합니다. 이 진단 정보는 일반 플레이 화면에 상시 노출하지 않습니다.

### 완료 기준

정상 기존 제작물은 계속 통과해야 합니다. 잘못된 중첩 조건·끊어진 참조·복수 시작 세이브의 불일치·이벤트 연쇄를 담은 예제에서 기대한 진단을 반환하고, 문제 위치 이동과 수정 후 갱신을 확인합니다. 영토·경제권·멀티·메이커 모듈·플레이 잠금 기능을 추가할 때 검사 규칙도 같은 변경에 넣습니다.

## 4. 앱 전반 성능 최적화

**대상은 특정 화면에 한정하지 않습니다.** 시작 화면, SAVE SELECT, 게임 화면, 시나리오 메이커, 지도, 날짜 진행, 자동 저장을 함께 측정합니다. 아래 코드 경로는 확인된 작업 후보이며, 실제 렉의 원인이나 개선율은 아직 측정하지 않았습니다.

| 우선 조사 경로 | 현재 코드에서 확인한 작업 | 먼저 확인할 개선 방향 |
|---|---|---|
| 공통 화면 갱신 | 스크립트 효과 뒤 `refreshUI()` 호출 | 한 행동에서 중복 호출되는지 측정, 변경된 영역·보이는 화면 갱신 |
| 제작기 입력·실행 취소 | `touch()`마다 시나리오 전체 `JSON.stringify`, 최대 60개 문자열 이력 | 입력 묶음·부분 변경 기록, 큰 시작 세이브/이미지 반복 복사 줄이기 |
| 제작기 다시 그리기 | `render()`에서 본문과 트리 조작기를 다시 만듦 | 선택·제목·진행률만 바뀔 때 부분 갱신, 입력 포커스 유지 |
| 세계지도 | 소유권 집계 때 구역별 국가 목록 탐색, 색 갱신 시 전체 재칠하기 | ID 인덱스·캐시, 바뀐 구역만 갱신, 한 프레임에 작업 합치기 |
| 저장·목록 | 자동 저장 시 전체 복사·목록 갱신, 데스크톱 저장 브리지의 동기 IPC | 저장 크기·빈도·차단 시간 측정, 직렬 저장·지연/비동기 처리 검토 |
| 시간 진행 | 날짜/시간별 시뮬레이션과 조건 검사·렌더 호출 | 계산과 그리기 분리, 숨겨진 화면 갱신 생략, 이벤트 순서 유지 |
| 이미지·맵 가져오기 | 큰 이미지 데이터·SVG·PNG 추적 | 메인 스레드 점유·메모리 측정, 취소 가능한 분할 작업/Worker 검토 |

최적화는 게임 규칙을 바꾸지 않습니다. 검사·자동 저장·이벤트를 제거해 빨라진 것으로 처리하지 않습니다. 실행 취소의 행동 단위, 마지막 입력 저장, 로드 시 상태 격리, 실시간 배속·일시정지, 기존 테마와 스크롤 조작을 유지합니다.

### 측정 절차와 목표

1. 느린 실제 세이브/제작물에서 우선 재현합니다. 없으면 소형·대형 고정 자료를 만들고 노드/이벤트/구역/국가 수, 이미지 포함 파일 크기를 기록합니다. 대형 자료는 방향성 500개·이벤트 500개·지도 5,000구역·100개 국가를 초기 후보로 쓰되 실제 자료로 보정합니다.
2. 같은 PC·앱 빌드 방식·화면 크기·자료로 변경 전후를 비교합니다. Electron 배포 형태에서 확인하고 웹 환경 수치와 섞지 않습니다. 첫 실행과 예열 후 반복 측정을 구분합니다.
3. 시작부터 조작 가능까지, 화면 전환/입력 지연, 지도·트리 이동의 프레임 시간, 날짜 계산 시간, 저장 시간, 50ms 이상 메인 스레드 작업, 메모리 사용량을 기록합니다. 평균뿐 아니라 p95와 튀는 구간을 남깁니다.
4. 원인별로 한 번에 작은 변경을 적용하고 동일 자료로 비교합니다. 입력·저장·진행 결과가 같은지도 함께 확인합니다.

**초기 수용 목표(측정 후 조정 가능):** 예열된 일반 입력/탭 전환 p95 100ms 이하, 지도·트리 이동 프레임 p95 33ms 이하. 큰 작업은 진행 표시와 취소/입력 응답을 유지합니다. 최소 사양·기준 자료와 실제 측정값을 함께 적기 전에는 “최적화 완료”로 표시하지 않습니다. 원래 빠른 화면도 회귀 여부를 확인합니다.

## 5. Steam 시나리오 멀티플레이

### 플레이 범위

같은 시나리오의 같은 세계에서 플레이어들이 **서로 다른 국가**를 맡는 방식을 기본안으로 합니다. 턴제와 실시간 모두 포함하며, 첫 연결 검증은 2인으로 시작합니다. 정식 최대 인원은 부하 측정 후 정하고 로비에서 제한합니다. 여러 명이 한 국가를 공동 조작하는 규칙은 후속 검토로 둡니다.

호스트가 방을 만들고 Steam 친구를 초대합니다. 참가자는 같은 시나리오·지도·모드 버전인지 확인한 뒤 가능한 국가를 선택하고 준비합니다. 불일치는 시작 전에 파일명·버전과 해결 방법을 안내합니다. 방 참가만으로 다른 사람의 파일을 덮어쓰지 않습니다.

| 규칙 | 제안 |
|---|---|
| 시간 | 방에 하나의 시계. 턴제는 참가국 모두 준비하면 하루 진행, 준비 취소 가능. 실시간은 호스트가 속도·재개 제어, 참가자는 일시정지 가능 |
| 선택형 이벤트 | 대상 국가 플레이어에게만 선택 권한. 필수 선택 대기 중에는 공통 시간 일시정지. 정보 기사 열람만으로 전체 시간을 멈추지 않음 |
| 국가 조작 | 자기 국가에 허용된 방향성·결정·연구·군사·경제·무역·선택만 명령 가능. 시나리오 편집 잠금을 함께 적용. 영토/경제권 등 전역 변화는 허용된 효과를 통해 반영 |
| 지도·경제권 편집 | 제작용 수동 칠하기를 멀티 참가자에게 그대로 허용하지 않음. 호스트 편집 허용 여부는 방 규칙으로 명시 |
| 이탈·재접속 | 연결이 끊기면 공통 시간 일시정지, 같은 Steam 계정의 재접속 후 최신 상태 복원. 호스트는 기다리거나 저장 후 종료 가능 |
| 저장·재개 | 호스트가 공통 저장을 생성, 참가국 배정·대기 선택·시간·적용 명령 위치까지 복원 |
| 호스트 종료 | 첫 구현은 자동 호스트 이전을 약속하지 않음. 마지막 공통 저장에서 새 방으로 재개하는 절차 제공 |

### 동기화 설계

로비만 연결하는 것으로 멀티플레이가 완성되지 않습니다. 현재 단일 플레이의 `campaign` 진행과 우리나라 중심 상태를 **공통 세계 상태 + 국가별 진행 + 플레이어별 화면 상태**로 분리해야 합니다. 국가를 바꿔 표시하는 것만으로 다른 플레이어의 플래그·변수·방향성을 공유하게 만들지 않습니다. 이벤트·플래그·효과의 기본 국가 범위와 명시적 전역 범위를 정의하고 기존 싱글 제작물은 기본 플레이 국가에 매핑합니다. 제작자가 멀티 지원 여부·참가 가능 국가·국가별 시작 데이터를 지정하게 합니다.

- **호스트가 상태를 확정합니다.** 참가자는 명령을 보내고, 호스트가 권한·현재 상태·인수를 검증한 뒤 순서대로 한 번 적용합니다. 동시 선택의 순서는 확정 명령 번호로 결정합니다.
- 공통 시각·랜덤 결과·이벤트 발생·영토/경제권 변경은 호스트에서 확정해 전파합니다. 현재 `Math.random()` 조건/효과를 참가자별로 다시 계산하지 않습니다. 난수 상태/결과와 평가 시점을 저장하며, 화면 갱신만으로 확률이 다시 추첨되지 않게 합니다.
- 초기 스냅샷 이후 명령 번호·상태 버전과 변경분을 전송하고, 누락·중복·오래된 요청을 처리합니다. 체크섬 불일치 시 시간 진행을 멈추고 전체 재동기화합니다. 같은 명령을 두 번 받아도 효과를 재실행하지 않습니다.
- 참가자별 카메라·열린 탭·확대율·읽음 상태는 로컬 UI로 유지합니다. 국가별 비공개 이벤트가 있다면 전송할 정보의 범위도 정의합니다.
- 모든 국가의 시뮬레이션과 경제 효과는 같은 시각에 한 번씩 계산합니다. 여러 참가자의 날짜 이벤트가 같은 월별 경제 계산을 중복 실행하지 않아야 합니다.

### Steam 연결과 현재 선행 조건

현재 `electron/steam.json`의 `appId`는 `null`이고 `package.json`에는 `steamworks.js`가 없습니다. 기존 `electron/mods.js`는 창작마당 초기화용 경로이며, 멀티 로비·전송 API는 구현되어 있지 않습니다. **App ID 발급·Steam 계정 2개·테스트 배포 권한**이 실제 Steam 통합 시험의 선행 조건입니다. App ID만 넣으면 멀티가 동작하는 것으로 안내하지 않습니다.

전송 계층은 Steam 로비와 Steam Networking 계열 사용을 목표로 하되, 선택한 Node/Electron 바인딩의 실제 지원 API·플랫폼·바이너리 패키징을 먼저 검증합니다. 지원하지 않으면 대체 바인딩/네이티브 브리지를 검토하고 이 문서를 갱신합니다. 아직 확인하지 않은 SDK 메서드를 구현 가능 근거로 삼지 않습니다.

네이티브 SDK는 Electron 메인 프로세스에 두고 preload에는 필요한 로비·명령 API만 공개합니다. 들어온 메시지는 길이·형식·권한·참조를 검사하며 임의 파일 경로·코드 실행으로 연결하지 않습니다. Steam 없이도 기존 싱글플레이는 가능해야 합니다. 창작마당 배포는 멀티 통신과 별개로 확인합니다.

순수 게임 상태/명령 검사는 로컬에서 먼저 만들 수 있지만 **실제 Steam 2인 검증 전에는 Steam 멀티 완료로 처리하지 않습니다.**

### 완료 기준

실제 서로 다른 두 Steam 계정에서 초대·참가·국가 선택·턴 동시 준비·실시간 배속/일시정지·각국 이벤트 선택·영토/경제권 효과·공통 저장/재개를 검증합니다. 버전 불일치·권한 없는 명령·중복/역순 메시지·연결 해제·재접속·호스트 종료를 시험하고 두 참가자의 공통 상태가 일치해야 합니다.

## 6. 경제권: 지도상의 경제 지역

### 지도와 제작 흐름

세계 화면의 **경제권**에서 경제 지역을 생성·선택하고 기존 `.hemimap`의 구역을 칠합니다. 지도에서는 **국가 영토 / 경제권** 표시를 전환합니다. 경제권 색칠은 국가 소유권·선거 지역구·의석을 바꾸지 않습니다. 기존 화면 이름과 네온·라이트·다크 스타일을 유지합니다.

경제권에는 고유 ID·이름·약칭·색·설명·소속 구역을 둡니다. 예를 들어 ‘북부 공업권’, ‘연안 무역권’, ‘수도 경제권’을 지도에 표시합니다. 여러 구역을 드래그로 배정하고 지우기·실행 취소/다시 실행·검색·미배정 구역 확인을 지원합니다. 국가 경계를 넘는 경제권도 표현할 수 있다는 기본안이며, 국가 단위 회원 명단을 경계의 원본으로 삼지 않습니다.

한 구역은 우선 **하나의 경제권 또는 미배정** 상태입니다. 겹치는 경제권·하위 경제권·별도 경제 지도 형상은 후속 설계로 둡니다. 경제권을 삭제하면 소속 구역을 미배정으로 돌리고 영향을 받는 스크립트 참조를 안내합니다.

### 상태와 경제 계산

- 형상·구역 키는 기존 세계지도를 재사용합니다. 새 저장 상태의 가칭은 `economicRegions`이며 **현재 미지원**입니다. 경제권 정의와 구역 배정은 `worldMap.owners`와 분리합니다.
- `.hemi`와 시나리오 시작 상태에 보관하고 `.hemimap` 확장 메타데이터로 왕복할 범위를 정합니다. 구버전 파일은 경제권이 없는 상태로 열리며, 지도 교체 시 없는 구역 키를 조용히 다른 구역에 연결하지 않습니다.
- 소유권 변경 뒤에도 경제권 경계는 유지하고 경제권에 포함된 국가별 구역 집계만 갱신합니다. 단순히 경제권을 만들었다는 이유로 나라 전체 GDP·물가를 임의 증감하지 않습니다.
- 첫 화면은 구역 수·소유 국가 분포와 **실제로 입력/연결된 지역 경제 자료**를 집계합니다. 구역별 인구·생산·산업 자료가 없으면 ‘자료 없음’으로 표시합니다. 기존 국가 전체 지표를 면적/구역 수로 나누어 실제 지역 통계처럼 표시하지 않습니다.
- 산업·투자·물류 등 경제권별 정책은 [시나리오 메이커 보완 설계](SCENARIO_MAKER_EXPANSION.md)의 자원·시설·생산과 연결합니다. 기본 지역 지표·효과 계산식·기간·가중치·중복 적용 방지·국가 경제 연결을 검증하며, 아직 없는 지역 시뮬레이션을 지원한다고 표기하지 않습니다.

### 시나리오·멀티 연결

시나리오 제작자는 시작 경제권을 설정하고 이벤트·방향성으로 구역을 다른 경제권에 배정할 수 있게 합니다. 경제권 소속 조건과 배정 효과의 이름·JSON 형식은 구현 전에 확정하며, 국가·구역 선택은 가이드와 프로 모드에서 같은 데이터를 사용합니다. 존재하지 않는 경제권/구역은 오류로 처리하고 일부 구역만 변경되는 실패를 막습니다.

멀티에서는 호스트가 배정을 확정하고 동일 결과를 전파합니다. 클라이언트의 지도 편집은 권한 검사를 거칩니다. 국가 영토 양도와 경제권 배정이 함께 있는 효과는 적용 순서·실패 계약을 명시합니다.

### 완료 기준

경제권 만들기·편집·삭제·여러 구역 칠하기·지우기·실행 취소를 검증합니다. 영토와 경제권 표시를 전환해도 서로의 데이터가 유지되고, 세이브/지도 파일 왕복·시나리오 시작/진행·다른 세이브 로드·멀티 재동기화 뒤 동일한 배정이 복원되어야 합니다. 누락 자료를 수치 0이나 가짜 추정치로 표시하지 않습니다.

## 7. 시나리오 메이커 확장·플레이 중 편집 잠금

[상세 설계](SCENARIO_MAKER_EXPANSION.md)에 **방향성·결정·기술 트리·군사력·경제·무역·자원·시설/생산·외교·서사/목표**의 제작 데이터, 플레이 동작, 연결 규칙을 정리합니다. 모든 기능은 가이드 입력과 프로 JSON 편집을 지원하고, 선택한 모듈만 사용하는 시나리오도 만들 수 있게 합니다.

방향성과 기술 연구는 별도 트리·진행으로 관리하며, 결정은 전용 목록/분류·조건·비용·기간·재사용 대기·효과를 편집합니다. 국가별 연구·군사·재고·생산·무역은 공통 시간과 비용 규칙을 사용하고 세이브/멀티에 함께 반영합니다. 편집 필드만 추가하고 플레이에서 작동하지 않는 기능은 완료로 보지 않습니다.

제작자가 **정당·의석·선거제도·정부·지도·경제·기술·군사·자원 등의 직접 수정**을 잠글 수 있게 합니다. 잠금은 정상 선거·연구·거래·방향성/이벤트 효과와 수동 편집을 구분하며, 버튼뿐 아니라 실제 변경 경계에서 검사합니다. 모든 경로의 차단·이유 표시·부분 변경 방지·저장/재접속 유지·멀티 호스트 검사를 검증합니다. 기존 제작물에 새 설정이 없으면 기존 동작을 유지합니다.

통합 예제 **산업화와 국경 위기**에서 방향성 → 기술 연구 → 투자 결정 → 자원 생산 → 무역 → 군사력 → 협상/결말을 연결합니다. 정당·의석·재고 직접 편집을 잠근 상태에서도 정상 행동과 효과로 변화가 일어나야 합니다.
