# 레이턴시 비교 — 1.7.0(최적화 전) → 현재

1.7.0 마지막 버전과 지금 브랜치 사이의 여섯 단계를 **같은 PC · 같은 방법 · 같은 날**에 다시 재서 비교한 기록입니다.
단계마다 그 커밋을 따로 띄우고, 프리셋 하나를 잴 때 여섯 단계를 번갈아 재서 PC 상태 변화가 한 단계에만 몰리지 않게 했습니다.

- 측정일: 2026-11-13 · 웹(헤드리스 Chromium 153) · 화면 1440×900 · 같은 컨테이너에서 연속 측정
- Electron(데스크톱) 수치는 아닙니다. 데스크톱 앱의 저장(파일 쓰기)은 따로 재야 합니다.
- 숫자는 ms. 따로 적지 않으면 중앙값. p95는 "100번 중 95번은 이보다 빠름"인 값(느린 쪽 끝)입니다.

## 3. 어떻게 쟀나

`tests/perf/stages.cjs`(이번에 추가) — 사람이 하는 조작에 가깝게, **누르는 순간(mousedown)부터 다음 프레임까지**를 잽니다. 누르는 순간을 넣은 이유는 1.7.0의 실행 취소가 그때 상태 전체를 복사했기 때문입니다(S4에서 고친 부분). 조작 사이는 0.8 ~ 1.1초 쉽니다.

| 항목 | 방법 |
|---|---|
| 날짜 ▶ | ▶(하루) 버튼에 mousedown · mouseup · click → 다음 프레임. 6번. **독일 · 대한민국 2026은 날짜가 비어 있어 ▶가 날짜 창을 엽니다**(그 시간) |
| 탭 전환 | mousedown → `switchSubTab` → 다음 프레임. 탭 10개 × 2바퀴(구성›정당 · 구성›설정 · 입법›표결 · 선거›총선 · 내각›각료 · 국가›시민 · 경제›개요 · 세계›순위 · 국가›결정 · 구성›의원) |
| 지금 저장 | `saveActiveNow(true)`(Ctrl+S와 같은 길) 4번 연달아 — 사이에 바뀐 것 없음 |
| 자동저장 | 나라 이름 칸을 고친 뒤(input 이벤트) 자동저장 주기 함수를 한 번 부르고, 그 뒤 2.5초 동안 가장 긴 멈춤(50ms 넘는 긴 작업 또는 동기 처리 시간). 이어서 바뀐 것 없이 한 번 더 |
| 프리셋 열기 | 프리셋을 고른 뒤 세이브가 만들어지고 화면이 뜰 때까지 (1회) |

주의할 점
- 50ms보다 짧은 멈춤은 "긴 작업"으로 잡히지 않습니다. S4부터 작은 프리셋의 자동저장이 0.0 ~ 0.2로 보이는 건, 저장이 뒤에서 50ms 미만 조각으로 나뉘어 돌기 때문입니다(멈춤이 없다는 뜻은 아님).
- 페이지 안에서 이벤트를 보내 잽니다. 실제 마우스 클릭(브라우저 입력 처리 포함)으로 재면 몇십 ms가 더 붙습니다 — 예: 대한민국 2024 ▶는 실제 클릭으로 약 110 → 약 50ms.
- 한 번 잰 값이라 ±10 ~ 20% 흔들립니다. 기능만 넣은 S1 → S2 → S3 사이의 오르내림은 대부분 이 범위입니다.

## 6. 단계마다 무엇이 달라졌나

**S0 → S1 (1.7.1 1~2단계)** — 저장과 세계지도.
- 자동저장이 바뀐 게 없어도 매번 다시 쓰던 문제(저장 시각까지 비교)를 고쳐 "바뀐 게 없을 때"가 782 → 78ms(대한민국 2024), 1,257 → 139ms(일본).
- 저장은 세이브 하나만 갈아 끼워 2.5 ~ 3배 빨라짐(889 → 337ms).
- 탭 전환은 안 보이는 목록을 건너뛰어 중앙값이 25 ~ 45% 줄었지만, 가장 느린 탭(내각›각료 · 구성›의원)은 그대로라 p95는 거의 같음.
- 세계지도: 구역 하나 칠하기 878 → 32ms(500구역), 940 → 56ms(5,000구역). 지도 가져오기 864 → 32ms.

**S1 → S2 → S3 (기능 추가)** — 세계지도 연동 · 경제권 · 편집 잠금 · 메이커 모듈 · 드래그 막기.
- 재는 항목 모두 측정 흔들림 범위 안. 편집 잠금이 함수 약 150개를 감쌌지만 눈에 띄는 비용은 없었습니다.

**S3 → S4 (실행 취소 · 자동저장)** — 날짜 ▶.
- 클릭마다 상태 전체(6 ~ 10MB)를 JSON으로 복사하던 실행 취소를 캐시로 바꿔, 날짜 ▶가 56 → 3.9ms(대한민국 2024), 105 → 3.3ms(일본). 날짜가 비어 날짜 창을 여는 대한민국 2026은 76 → 13ms.
- 같은 이유로 탭 전환 중앙값도 20 ~ 37% 더 줄음(누르는 순간의 복사가 사라짐).
- 자동저장은 바뀐 게 있을 때도 미리 압축해 두는 뒤쪽 저장으로 324 → 71ms(대한민국 2024).
- 바뀐 것 없이 연달아 저장하면 같은 글자를 다시 써서 304 → 59ms. 바뀐 직후의 저장은 그대로(4장 표).

**S4 → S5 (탭 전환)** — 가장 느린 탭.
- p95가 614 → 202ms(대한민국 2024), 1,073 → 161ms(미국), 906 → 96ms(영국). 가장 느린 탭이 내각›각료 · 구성›의원 · 국가›시민에서 모두 200ms 아래로.
- 원인별로: 모던 테마 `[style*=…]` 선택자 → 클래스(모든 탭의 스타일 계산), "의원에서 불러오기" 목록을 열 때 채우기(내각›각료), 시민 60명씩, 버튼 묶음 표시 한 번에 읽고 쓰기, 경제 예측 재사용.
- `refreshUI()` 41 → 17ms, 스크립트 효과 47 → 17ms(대한민국 2024) — 그리는 요소가 줄어든 덕.
- 독일 · 미국 프리셋 열기가 약 1초 → 약 0.5초 — 열 때 그리던 의원 목록(`<option>` 수천 개)이 사라짐.
