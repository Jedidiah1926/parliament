# 레이턴시 비교 — 1.7.0(최적화 전) → 현재

1.7.0 마지막 버전부터 지금까지의 일곱 단계를 **같은 PC · 같은 방법 · 같은 날**에 다시 재서 비교한 기록입니다.
단계마다 그 커밋을 따로 띄우고, 프리셋 하나를 잴 때 일곱 단계를 번갈아 재서 PC 상태 변화가 한 단계에만 몰리지 않게 했습니다.

- 측정일: 2026-11-14 · 웹(헤드리스 Chromium 153) · 화면 1440×900 · 같은 컨테이너에서 연속 측정
- Electron(데스크톱) 수치는 아닙니다. 데스크톱 앱의 저장(파일 쓰기)은 따로 재야 합니다.
- 숫자는 ms. 따로 적지 않으면 중앙값. p95는 "100번 중 95번은 이보다 빠름"인 값(느린 쪽 끝)입니다.

## 3. 어떻게 쟀나

`tests/perf/stages.cjs` — 사람이 하는 조작에 가깝게, **누르는 순간(mousedown)부터 다음 프레임까지**를 잽니다. 누르는 순간을 넣은 이유는 1.7.0의 실행 취소가 그때 상태 전체를 복사했기 때문입니다(S4에서 고친 부분). 조작 사이는 0.8 ~ 1.1초 쉽니다.

| 항목 | 방법 |
|---|---|
| 날짜 ▶ | ▶(하루) 버튼에 mousedown · mouseup · click → 다음 프레임. 6번. **독일 · 대한민국 2026은 날짜가 비어 있어 ▶가 날짜 창을 엽니다**(그 시간) |
| 탭 전환 | mousedown → `switchSubTab` → 다음 프레임. 탭 10개 × 2바퀴(구성›정당 · 구성›설정 · 입법›표결 · 선거›총선 · 내각›각료 · 국가›시민 · 경제›개요 · 세계›순위 · 국가›결정 · 구성›의원) |
| 지금 저장 | `saveActiveNow(true)`(Ctrl+S와 같은 길) 4번 연달아 — 사이에 바뀐 것 없음 |
| 자동저장 | 나라 이름 칸을 고친 뒤(input 이벤트) 자동저장 주기 함수를 한 번 부르고, 그 뒤 2.5초 동안 가장 긴 멈춤(50ms 넘는 긴 작업 또는 동기 처리 시간). 이어서 바뀐 것 없이 한 번 더 |
| 프리셋 열기 | 프리셋을 고른 뒤 세이브가 만들어지고 화면이 뜰 때까지 (1회) |

주의할 점
- 50ms보다 짧은 멈춤은 "긴 작업"으로 잡히지 않습니다. S4부터 작은 프리셋의 자동저장이 0.0 ~ 0.2로 보이는 건, 저장이 뒤에서 50ms 미만 조각으로 나뉘어 돌기 때문입니다(멈춤이 없다는 뜻은 아님).
- 페이지 안에서 이벤트를 보내 잽니다. 실제 마우스 클릭(브라우저 입력 처리 포함)으로 재면 몇십 ms가 더 붙습니다 — 예: 대한민국 2024 ▶는 실제 클릭으로 약 110 → 약 50ms.
- 한 번 잰 값이라 ±10 ~ 20% 흔들립니다. 기능만 넣은 S1 → S2 → S3, 그리고 S5 → S6의 게임 안 수치 오르내림은 대부분 이 범위입니다.

### 페이지 열기 — S4 · S5 · S6 (따로 잼)

S5에서 넣은 모던 테마 모듈이 페이지를 열 때 일을 해서 첫 화면(FCP) · 로드 완료가 늦어졌고, S6에서 되돌렸습니다. 같은 조건으로 16번씩 번갈아 연 중앙값입니다(S4에는 모듈이 없음).

| 테마 | 페이지 | 첫 화면 S4 → S5 → S6 | 로드 완료 S4 → S5 → S6 |
|---|---|---:|---:|
| 라이트 | `main.html` | 172 → 252 → **172** | 343 → 415 → **336** |
| 라이트 | `index.html` | 112 → 128 → **104** | 178 → 200 → **172** |
| 라이트 | `scenario.html` | 100 → 124 → **96** | 182 → 195 → **173** |
| 네온 | `main.html` | 180 → 264 → **176** | 339 → 410 → **330** |
| 네온 | `index.html` | 112 → 128 → **116** | 104 → 130 → **111** |
| 네온 | `scenario.html` | 100 → 116 → **88** | 104 → 124 → **101** |

S6에서 바꾼 것: 모듈을 페이지 로드가 끝난 뒤 한가할 때(로드 후 약 70 ~ 110ms) 시작합니다. 그 전까지는 원래 `[style*=…]` 규칙이 그대로 적용되고, 바꾸는 순간에도 선택자 교체와 클래스 붙이기를 한 번에 해서 화면은 같습니다. 네온 테마에서는 아예 돌지 않다가 라이트 · 다크로 바꾸는 순간 시작합니다. 바꾼 규칙 · 요소 클래스는 S5와 글자까지 같음을 확인했습니다.
- 시도했다가 버린 방법: 바꾼 CSS 전체로 새 `<style>`을 만들기 — 더 빠르지만, 브라우저가 `var()`가 든 단축 속성(`background: var(--…)`)을 글자로 되돌릴 때 값을 잃어 테마 규칙 일부가 사라졌습니다.

## 6. 단계마다 무엇이 달라졌나

**S0 → S1 (1.7.1 1~2단계)** — 저장과 세계지도.
- 자동저장이 바뀐 게 없어도 매번 다시 쓰던 문제(저장 시각까지 비교)를 고쳐 "바뀐 게 없을 때"가 781 → 70ms(대한민국 2024), 1,175 → 126ms(일본).
- 저장은 세이브 하나만 갈아 끼워 약 2.8 ~ 3.2배 빨라짐(866 → 313ms, 1,331 → 421ms).
- 탭 전환은 안 보이는 목록을 건너뛰어 중앙값이 25 ~ 55% 줄었지만, 가장 느린 탭(내각›각료 · 구성›의원)은 그대로라 p95는 일본을 빼면 거의 같음.
- 세계지도: 구역 하나 칠하기 807 → 32ms(500구역), 890 → 42ms(5,000구역). 지도 가져오기 789 → 30ms.

**S1 → S2 → S3 (기능 추가)** — 세계지도 연동 · 경제권 · 편집 잠금 · 메이커 모듈 · 드래그 막기.
- 재는 항목 모두 측정 흔들림 범위 안. 편집 잠금이 함수 약 150개를 감쌌지만 눈에 띄는 비용은 없었습니다.

**S3 → S4 (실행 취소 · 자동저장)** — 날짜 ▶.
- 클릭마다 상태 전체(6 ~ 10MB)를 JSON으로 복사하던 실행 취소를 캐시로 바꿔, 날짜 ▶가 59 → 5.1ms(대한민국 2024), 111 → 3.3ms(일본). 날짜가 비어 날짜 창을 여는 대한민국 2026은 68 → 11ms.
- 같은 이유로 탭 전환 중앙값도 10 ~ 55% 더 줄음(누르는 순간의 복사가 사라짐).
- 자동저장은 바뀐 게 있을 때도 미리 압축해 두는 뒤쪽 저장으로 341 → 59ms(대한민국 2024).
- 바뀐 것 없이 연달아 저장하면 같은 글자를 다시 써서 326 → 69ms. 바뀐 직후의 저장은 거의 그대로(4장 표).

**S4 → S5 (탭 전환)** — 가장 느린 탭.
- p95가 755 → 223ms(대한민국 2024), 787 → 123ms(미국), 819 → 145ms(영국). 가장 느린 탭이 내각›각료 · 구성›의원 · 국가›시민에서 모두 230ms 아래로.
- 원인별로: 모던 테마 `[style*=…]` 선택자 → 클래스(모든 탭의 스타일 계산), "의원에서 불러오기" 목록을 열 때 채우기(내각›각료), 시민 60명씩, 버튼 묶음 표시 한 번에 읽고 쓰기, 경제 예측 재사용.
- `refreshUI()` 29 → 18ms, 스크립트 효과 32 → 17ms(대한민국 2024) — 그리는 요소가 줄어든 덕.
- 독일 · 미국 프리셋 열기가 약 0.9초 → 약 0.5초 — 열 때 그리던 의원 목록(`<option>` 수천 개)이 사라짐.
- 대신 페이지 열기가 늦어짐: `main.html` 로드 완료 343 → 415ms, 첫 화면 172 → 252ms.

**S5 → S6 (페이지 로드)** — S5에서 늘어난 페이지 열기 시간을 되돌림.
- `main.html` 로드 완료 415 → 336ms, 첫 화면 252 → 172ms (모듈 없는 S4와 같음). 네온 테마에서도 같음.
- 게임 안 수치(날짜 ▶ · 탭 전환 · 저장)는 S5와 흔들림 범위 안에서 같음 — 모듈이 하는 일은 그대로이고 시작하는 때만 바뀜.
